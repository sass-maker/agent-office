# Office OS shareability and replacement review — 2026-09-07

## Decision

Keep the native employee-contract research inactive. Replace the generic daily
assistant/workflow use case with an existing product before investing in a broader
Office OS application. Do not delete the repository or claim a migration has been
proved. Named, revisioned employee contracts and inspectable authority are the
potential differentiated research; the illustrated office is not sufficient value
on its own.

## Current evidence

XcodeBuildMCP ran 27 focused Swift tests across CustomerVoiceFeedbackTests,
EmployeeOutcomeEngineTests and LegacyWorkAdaptersTests: all passed. These exercise
bounded feedback scanning, source/citation requirements, refusal of empty or
uncited briefs, interrupted-work recovery and one-time advancement of recurring
duties. They use test inputs/runtime doubles, not a fresh real employee deliverable.

The Swift package built and launched the native AgentOffice executable. Native
computer-use inspection failed twice with `Sky Computer Use native pipe startup
failed`. The launched process was then stopped using the owning SwiftPM process
handle. No company folder was selected, assignment started, research permission
granted or private artifact read. This is build/launch evidence, not UI completion.

There are zero open GitHub issues as of this review. The README's historical issue
links are not proof of an active queue. No issues were closed during this task.

## Existing alternative

Anthropic's [Cowork product guide](https://claude.com/blog/the-claude-cowork-product-guide)
documents local file work, connected apps, multi-step deliverables, subagents and
scheduled tasks. Its [project documentation](https://claude.com/docs/cowork/guide/projects)
documents persistent project context, instructions and memory. These overlap
substantially with ordinary recurring research and feedback-summary work.

This is a documented-capability comparison, not an owner trial or performance
benchmark. It does not establish offline/local-model equivalence, identical
permission semantics, cost, or reliable completion of this owner's duties.
Office OS's separate employee identity, contract revision and authority receipts
remain distinct design choices worth preserving as research.

## Work retained before a broader shareability claim

1. Run one synthetic feedback duty through the native UI; inspect the produced
   source references, decision, owner review and saved state after reopening.
2. Test interruption and cancellation in the app, then complete the same occurrence
   without duplicate delivery or advancing its due date twice.
3. Run the same allowed inputs and acceptance criteria in Cowork. Compare artifact
   correctness, owner effort, recovery and permission clarity, not office visuals.
4. Retain product investment only if the employee-contract experience provides a
   repeatable advantage. Otherwise use the existing assistant and keep this as a
   non-promoted architecture experiment.
5. Verify a distributable installation and native visual/accessibility behavior.
   No release or deployment was performed in this audit.
