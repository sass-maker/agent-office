## Context

Occurrences and receipts exist and are correct, but invisible. The risk in
adding a calendar is that it becomes the product shell, or starts inventing
blocks that no policy authored — both of which #24 explicitly warns against.

## Decisions

### The calendar projects; it never authors

Blocks are derived from occurrences. An empty week shows an empty week, not a
grid of imagined slots. The Office remains the organization home and Mission
remains commitment supervision; Calendar is a view across them.

### Catch-up is a policy, not a prompt

A missed window is resolved by what the owner already decided for that schedule,
not by a dialog after the fact. Two options only — leave it, or move it to the
next window — because a third ("run it now") would execute work late, which the
schedule slice deliberately refuses to do.

### Replacements are traceable

A rescheduled occurrence records which occurrence it replaces, so a week that
looks busy can be read back to the window that was actually missed.
